### Phase 1: Database Schema Discovery
**Target:** Existing Bella Spa database tables

**Questions:**
- What columns exist in `bookings` table?

**Action:** Read database migration files, schema.sql, or ORM entity definitions

---

### Phase 2: Application Code Discovery
**Target:** `src/products/bella-spa/*` or legacy Spa code  
**Evidence:** H0 found database tables but no platform contracts

**Questions:**
- Is there `BookingService`, `QueueService`, `VoucherService` in application layer?
- Are there business rules for appointment state machine?
- Is there stylist assignment logic?
- Is there commission calculation?

**Action:** Grep for service classes, controllers, domain logic

---

### Phase 3: Platform Primitives Discovery
**Target:** `src/platform/core/*`, `src/platform/host/*`  
**Evidence:** Generic capabilities may exist under different names

**Questions:**
- Is there generic `Scheduling`, `ResourceAllocation`, `QueueManagement`?
- Is there generic `Catalog`, `Inventory`, `Promotion` engine?
- Could Healthcare `Resource Engine` be generic enough for stations?

**Action:** Search for domain-agnostic primitives that Spa could use

---

### Phase 4: Contract Extraction Assessment
**For each capability found:**

**If implementation exists:**
- Can it be contract-extracted WITHOUT breaking Bella Spa?
