✅ Điểm Mạnh Vượt Trội

1. Accounting Outbox Pattern

Implementation: src/lib/accounting-outbox.ts, pending_accounting_entries table

Mọi nghiệp vụ tài chính (session checkout, package sale, expense, salary confirmation) tạo accounting entry trong cùng transaction với nghiệp vụ chính. Worker bất đồng bộ xử lý và posting lên accounting_entries table. Đảm bảo eventual consistency, không bao giờ mất giao dịch kế toán.

2. Multi-Tenancy với Row Level Security

Mỗi tenant (chi nhánh) tách biệt hoàn toàn dữ liệu qua RLS policies trong PostgreSQL. Staff chỉ query được data của chi nhánh mình. Super admin thấy tất cả. Không cần WHERE tenant_id trong code - database tự filter.

Kết quả: Zero data leakage giữa chi nhánh, compliance GDPR/PDPA native.

3. Revenue Recognition (TT133)

File: src/services/revenue-recognition.ts

Ghi nhận doanh thu chuẩn Thông tư 133: gói trả trước ghi nợ TK 131 (phải trả khách), mỗi ca hoàn thành ghi nhận doanh thu TK 5113, chi phí dịch vụ TK 632. Tự động tạo journal entries với debit/credit chuẩn kế toán.

4. Inter-Branch Clearing (Đặc Thù Bella)

File: src/services/clearing-actions.ts

Chi nhánh A làm dịch vụ cho khách của chi nhánh B → hệ thống tạo clearing transaction → định kỳ bù trừ công nợ giữa các chi nhánh → tạo accounting entries với TK 3387 (Công nợ nội bộ).

Độc nhất: Chưa thấy hệ ERP nào khác xử lý bù trừ liên chi nhánh tự động như vậy.

5. Franchise Royalty Automation

File: src/services/franchise-actions.ts

Mỗi tháng tự tính phí nhượng quyền (fixed VNĐ hoặc % doanh thu), tạo invoice, tracking thanh toán, ghi nhận chi phí vào P&L. Tích hợp accounting outbox.

🔒 Đánh Giá Chi Tiết: Bảo Mật (92/100)

✅ Điểm Mạnh

1. Row Level Security (RLS)

PostgreSQL RLS policies cho mọi bảng nhạy cảm: bookings, sessions, packages, accounting_entries, salary_records. Staff chỉ thấy data của tenant mình. Student chỉ thấy enrollment của mình.

Test coverage: Có test cases verify RLS trong __tests__/integration/tenant-isolation.test.ts

2. API Gateway với Rate Limiting

5 tiers:

  • Free: 60 requests/minute
  • Basic: 300 req/min
  • Standard: 1000 req/min
  • Premium: 5000 req/min
  • Unlimited: No limit (enterprise contract)

Redis-based sliding window rate limiter, return HTTP 429 với Retry-After header.

3. Circuit Breaker Pattern

Redis unavailable → Circuit opens → degraded mode (skip rate limit check, log warnings). Tự động recover khi Redis back online. Tránh cascade failures.

4. Webhook HMAC Signatures

Mọi webhook delivery có HMAC-SHA256 signature trong X-Bella-Signature header. Partners verify authenticity. Prevent replay attacks với timestamp check.

5. Audit Logs

Table audit_logs ghi lại mọi action nhạy cảm: approve salary, finalize invoice, delete booking, change tenant settings. Có actor_id, action, resource_type, old_data, new_data JSON.

6. Static Security Analysis

CI/CD pipeline chạy:

  • Semgrep - SAST cho code vulnerabilities
  • Trivy - Scan dependencies và Docker images
  • Gitleaks - Secret detection
  • npm audit - Known CVEs trong npm packages

Findings block merge nếu severity HIGH/CRITICAL (trừ documented exceptions trong .trivyignore).

⚠️ Điểm Cần Cải Thiện (-8 điểm)

  • [-3] Chưa có WAF (Web Application Firewall) cho production - dễ bị DDoS layer 7
  • [-2] Chưa implement IP allowlist cho API partners - hiện chỉ dựa vào API key
  • [-2] Session timeout chưa configurable per tenant (hard-coded 7 days)
  • [-1] Chưa có automated security audit quarterly (chỉ manual review)

✅ Điểm Mạnh

1. Mandatory Side-Effect Assertions

Rule trong AGENTS.md: Mọi test cho actions có side-effects (approve leave → insert attendance, checkout session → deduct inventory, confirm booking → insert revenue) MUST assert side-effect tables.

Example: Test approve salary MUST verify accounting_entries được tạo đúng debit/credit.

2. Zero Silent Database Failures

Không được try/catch database errors rồi chỉ console.error. Phải re-throw hoặc return explicit failure. Tests sẽ fail ngay nếu DB operation lỗi.

3. Strict Database Payload Typing

Dùng Supabase generated types: Database['public']['Tables']['attendance']['Insert']. Compile-time error nếu insert column không tồn tại. Tránh runtime bugs.

4. Pro-Rata Salary Testing

Test cases verify lương được tính đúng theo ngày làm việc thực tế: (base_salary / 26) × actualDays. Draft status recalculate động, Published status preserve manual adjustments.

5. Package Session Multiplier Tests

Combo Mẹ & Bé VIP (2.0x), Hạnh Phúc (1.5x), Tiết Kiệm (1.0x). Tests verify total_sessions dùng multiplier đúng, không đếm raw sessions.

⚠️ Điểm Cần Cải Thiện (-12 điểm)

  • [-5] E2E test coverage chưa đủ rộng - chỉ ~30 flows, còn nhiều edge cases chưa test (multi-branch booking transfer, franchise royalty disputes)
  • [-3] Load tests chưa bao gồm sustained load (12+ hours) để phát hiện memory leaks
  • [-2] Mutation testing chưa setup - không biết test suite có phát hiện được logic bugs không
  • [-2] Visual regression testing chưa có (UI changes có thể break layouts)
