Mục Tiêu Chiến Lược

Biến Bella Spa ERP từ hệ thống khép kín thành nền tảng mở có thể tích hợp, cho phép kết nối hai chiều với toàn bộ hệ sinh thái phần mềm tại Việt Nam.

📥
Nhận Dữ Liệu Vào
Từ Zalo, thanh toán (MoMo/ZaloPay/VNPay), booking online, POS bán hàng.
📤
Đẩy Dữ Liệu Ra
Cho kế toán, hóa đơn điện tử, CRM, dashboard đối tác franchise.
🔗
Mở API Cho Đối Tác
Franchise, white-label, phần mềm POS bên thứ ba kết nối vào HR engine.
💡
Nguyên tắc cốt lõi: Modular Monolith là hướng đúng. Không tách microservices ở giai đoạn này. API Gateway chỉ là lớp adapter bên ngoài — không thay đổi business logic bên trong.

Nguyên Tắc Thiết Kế API Gateway

1
Gateway là Adapter, không phải Business Logic — Tất cả nghiệp vụ vẫn qua src/services/. Gateway chỉ parse/validate request và format response.
2
Tenant-scoped tuyệt đối — Mọi request vào phải xác định được tenant_id qua API Key hoặc JWT.
3
Idempotency Key bắt buộc — Payment webhook và accounting outbox đã có pattern này, cần lan rộng ra toàn bộ inbound webhook.
4
HMAC Signature Verify — Tất cả webhook từ bên ngoài (MoMo, ZaloPay, Zalo) phải verify signature trước khi xử lý.
5
Audit tất cả API call — Kế thừa audit-actions.ts để log mọi inbound API call có mutation.

Retry Strategy

Exponential backoff: retry sau 1m → 5m → 30m → 2h → 24h
Sau 5 lần thất bại → trạng thái dead, notify admin qua Telegram bot
Outbound payload được HMAC sign để partner verify được

Luồng Xử Lý: POS Sale → Bella Salary

1.KiotViet/Sapo gửi webhook "invoice.paid" / "orders/paid"
└─ POST /api/v1/pos-events/sales
2.POS Adapter Layer xử lý:
a. Verify HMAC signature
b. Check idempotency key
c. Lookup pos_staff_mappings → bella_ktv_id
d. Lookup pos_service_mappings → commission_rate
e. Nếu không map được → pos_unmapped_events (admin review)
3.Enqueue vào pos_commission_adjustments (Option B — An toàn nhất)
4.Salary Engine: recalculateAndSaveSalaryRecord() tự động pickup
5.Accounting Outbox: enqueue REVENUE_RECOGNIZED với metadata pos_provider
6.Response về POS: { success: true, bella_session_ref: '...' }
⚠️
Option A vs Option B: Option A (virtual session_log với source='pos') tái dùng pipeline nhưng rủi ro cao — cần audit toàn bộ query trong session-completion-helpers.ts. Khuyến nghị: bắt đầu bằng Option B với bảng pos_commission_adjustments riêng biệt.
