1 Kiến Trúc Hệ Thống

Next.js 16 modular monolith trên Supabase (PostgreSQL + Auth + RLS). Server Actions là luồng dữ liệu chính; API routes chỉ dùng cho webhook, cron và tích hợp AI.

Browser ↓ proxy.ts ← session refresh + redirect theo role (ktv/student/admin) ↓ App Router ← /dashboard · /ktv · /hq · /portal · /book ↓ Server Actions ← ~75+ file 'use server' (luồng chính) ↓ ↘ API routes (8): webhook · cron · AI Supabase RLS ← get_auth_tenant_id() · is_hq_super_admin() ↓ Side effects ← accounting_outbox → cron worker → journal posting

Cấu Trúc Thư Mục & Module Boundary

  • src/app/ — 42 trang dashboard, KTV portal, HQ, public booking, customer portal, student training.
  • src/services/ — ~76 file domain logic (finance, accounting, CRM, inventory, HQ…); phần lớn logic vẫn ở đây.
  • src/modules/ — chỉ 2 module đã extract: booking/ (24 actions) và hr-salary/ (9 actions).
  • src/lib/business-rules/ — 15 module pure functions (~2.400 dòng): salary, payment, inventory, permissions…
  • supabase/migrations/ — 178 migration: schema, RLS, RPC, subscription quota, accounting outbox.

Tenant Isolation — Defense in Depth (4 lớp)

  • Lớp 1 — proxy.ts: Refresh session, redirect unauthenticated, routing theo role (ktv → /ktv, student → /student).
  • Lớp 2 — auth-guards: getAuthorizedTenantUser() yêu cầu tenant_id + role allowlist.
  • Lớp 3 — App query: Mọi server action filter .eq('tenant_id', tenantId).
  • Lớp 4 — PostgreSQL RLS: is_hq_super_admin() OR tenant_id = get_auth_tenant_id() — đã fix bypass NULL tenant.

Điểm Mạnh Code Quality

  • AGENTS.md — 9 quy tắc bắt buộc: Zero silent DB failures, side-effect assertions trong test, typed payloads, salary recalculation engine, P&L status filters…
  • Business rules pure functions: salary.ts, payment.ts, accounting-outbox.ts — decoupled khỏi Supabase, testable, production guard script.
  • Services layer sạch any: src/services/ không có explicit any; nợ typing tập trung UI/legacy pages.
  • ESLint ratchet: lint:strict enforce no-explicit-any toàn production code ngoài baseline đang burn down.

Nợ Kỹ Thuật & Pattern Cần Theo Dõi

  • Dual error model: Một số action throw, một số return { success: false } — cần convention rõ cho contributor mới.
  • ~80 file any baseline: Chủ yếu dashboard pages và legacy actions — burn down qua npm run lint:strict.
  • Jest naming: e2e-pipeline.test.ts trong Jest dễ nhầm với Playwright e2e/.
  • No coverage threshold: test:coverage tồn tại nhưng chưa gate trong CI.

Differentiator So Với POS/ERP Thông Thường

  • Session completion engine: Atomic side effects — trừ kho, ghi revenue, recalc salary, enqueue accounting outbox; rollback toàn bộ khi fail.
  • Salary reconciliation AI vs Kế toán: Đối soát lương tự động với package multiplier (1.0 / 1.5 / 2.0), pro-rata, KPI sync.
  • Dual-mode accounting: Legacy ledger + professional COA/journals; period closing workflow.
  • Franchise-ready: HQ consolidated P&L, inter-branch clearing, royalty, subscription quota SaaS.
  • Offline KTV: Dexie local cache — check-in/checkout khi mất mạng, sync khi có kết nối.

Điểm Mạnh Bảo Mật

  • RLS NULL bypass fix: Thay get_auth_tenant_id() IS NULL bằng is_hq_super_admin() — ngăn user không tenant xem toàn bộ data.
  • Payment webhook: timingSafeEqual, idempotency key, rollback side effects, PII redaction qua log-redactor.ts.
  • Token encryption: Meta Ads và Telegram bot tokens mã hóa AES-256-GCM at-rest.
  • Tenant isolation tests: tenant-isolation-source-guards.test.ts — UI không query Supabase trực tiếp cho tenant data.
  • Anon RPC revocation: Accounting/reporting RPCs đã revoke khỏi anon role.

Gaps Kiểm Thử

  • E2E depth: Nhiều flow là smoke (△) — form validation, concurrency UI, full workflow chưa cover.
  • Side-effect assertions không đều: Mạnh ở salary/accounting; mỏng hơn ở một số action tests.
  • No coverage threshold: Coverage optional, không gate CI.
  • Secret scan excludes __tests__: Test files có thể chứa mock secrets không bị phát hiện.

7 Khuyến Nghị Ưu Tiên

Lộ trình xử lý theo mức ưu tiên P0 (bảo mật/tài chính) → P1 (chất lượng/vận hành) → P2 (kiến trúc dài hạn).

P0 1–2 Sprint — Bảo mật & Tài chính
Webhook amount validation & Secret hygiene
Validate số tiền webhook vs deposit/booking trước khi ghi revenue và flip booking status. Chuyển webhook secret sang header only, bỏ query string. Audit và thu hẹp legacy GRANT ALL TO anon trên các bảng cũ.
P1 2–4 Sprint — Chất lượng & Vận hành
MFA enforce · Cron hardening · E2E workflow
Enforce MFA (AAL2) cho admin/accountant tại proxy.ts. Dùng timingSafeEqual cho tất cả cron secrets. Bắt buộc TELEGRAM_WEBHOOK_SECRET ở production. Thêm 3–5 E2E workflow thật (checkout session, chốt lương, đóng kỳ kế toán) với assert DB side effects.
P2 Dài hạn — Kiến trúc & Nợ kỹ thuật
Module extraction · Outbox adapter · Coverage gate
Tiếp tục extract src/modules/ — ưu tiên CRM, inventory orchestration. Tách outbox event adapter (core event vs spa payload). Burn down ESLint any baseline (~80 file) qua lint:strict. Thêm Jest coverage threshold cho services/ và modules/.

Verdict Cuối

Bella Spa ERP là codebase chất lượng cao, orient production — với điểm nổi bật là tính toàn vẹn nghiệp vụ (lương, kế toán, side effects) được codify trong AGENTS.md và test suite. Kiến trúc có hướng đi rõ (modular monolith → multi-industry platform). Bảo mật được harden iteratively. Không phải greenfield sạch, nhưng với mục tiêu vận hành spa thực tế + mở rộng SaaS, đây là nền tảng đáng tin cậy và có thể scale có kiểm soát.
