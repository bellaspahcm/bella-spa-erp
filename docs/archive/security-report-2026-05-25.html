Service Role Key bị commit vào Git

✓ Đã sửa

OWASP A07 · CWE-798 — Hardcoded Credentials

📄 mcp-server/.env

File mcp-server/.env chứa SUPABASE_SERVICE_ROLE_KEY bị Git theo dõi. Key này có quyền bypass hoàn toàn Row Level Security, cho phép đọc/ghi/xoá toàn bộ dữ liệu mọi tenant không cần xác thực.

SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...  # ← bị lộ trong git history
✅ Đã xử lý

Xoá mcp-server/.env khỏi git tracking. Thêm vào .gitignore. Key cũ đã được revoke trên Supabase Dashboard. Key mới dạng sb_secret_... đã được cập nhật.

[C2]

RPC get_user_by_email_v1 không có auth check

✓ Đã sửa

OWASP A01 · CWE-639 — Authorization Bypass

📄 supabase/migrations/20260523020000_get_user_by_email_rpc.sql

Hàm dùng SECURITY DEFINER (bypass RLS) nhưng không kiểm tra người gọi là ai. Bất kỳ ai có anon key (đã public) đều tra cứu được role, tenant_id, status của mọi nhân viên.

-- TRƯỚC: không có auth check
CREATE OR REPLACE FUNCTION get_user_by_email_v1(p_email text)
RETURNS TABLE (...) AS $$
BEGIN
    RETURN QUERY SELECT * FROM users WHERE email = p_email;  -- ← ai cũng gọi được
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
✅ Đã sửa

Thêm kiểm tra is_admin() đầu hàm — chỉ admin mới được gọi. Migration 20260525000000_security_hardening.sql.

[H2]

Hardcoded fallback trong DB_ENCRYPTION_KEY

✓ Đã sửa

OWASP A02 · CWE-321 — Hard-coded Cryptographic Key

📄 src/lib/crypto.ts · Dòng 5

Key mã hoá AES-256-GCM cho Zalo tokens có fallback là chuỗi cố định trong source code. Nếu DB_ENCRYPTION_KEY không được set trong production, mọi token Zalo sẽ được mã hoá bằng key đã lộ.

const rawKey = process.env.DB_ENCRYPTION_KEY || 'bella-spa-erp-default-dev-secret-key-32-chars-long';
✅ Đã sửa

Bỏ fallback — server throw ngay nếu env var không được set. Đã tạo key mới trong .env.local.

[H3]

Hardcoded fallback CRON_SECRET trong source code

✓ Đã sửa

OWASP A05 · CWE-798 — Use of Hard-coded Credentials

📄 src/app/api/cron/zalo-reminders/route.ts · Dòng 10

Endpoint cron dùng mật khẩu mặc định 'PLACEHOLDER_CRON_SECRET' nếu biến môi trường không được cài — mật khẩu này có thể thấy trong git history.

[H4]

Thiếu HTTP Security Headers

✓ Đã sửa

OWASP A05 · CWE-693 — Protection Mechanism Failure

📄 next.config.ts

Next.js không cấu hình các HTTP header bảo mật: không có CSP (Content Security Policy), không có X-Frame-Options, không có HSTS, không có X-Content-Type-Options → dễ bị clickjacking, MIME sniffing, và XSS.

✅ Đã sửa

Thêm đầy đủ security headers cho mọi route: X-Frame-Options: DENY, X-Content-Type-Options: nosniff, Strict-Transport-Security (1 năm + preload), Content-Security-Policy, Permissions-Policy.

[H5]

error.message lộ ra client trong API routes

✓ Đã sửa

OWASP A09 · CWE-209 — Information Exposure Through Error Message

📄 src/app/api/webhooks/payment/route.ts · src/app/api/cron/zalo-reminders/route.ts

Khi xảy ra lỗi server, raw error.message được trả về cho client. Lỗi database thường chứa tên bảng, tên cột, constraint — thông tin giúp attacker hiểu cấu trúc hệ thống.

✅ Đã sửa

Log chi tiết phía server, trả về generic message cho client.

[H6]

Email người dùng ghi vào server log (PII)

✓ Đã sửa

OWASP A09 · CWE-532 — Insertion of Sensitive Information into Log File

📄 src/modules/booking/actions/lifecycle-actions.ts · Dòng 190

Email khách hàng (PII) bị ghi vào server logs có thể bị expose qua Sentry, DataDog hoặc các logging system.

console.log('[createBooking] Level2 authUser:', authUser.email, '| id:', authUser.id);
✅ Đã sửa

Xoá email khỏi log, chỉ giữ lại user ID (không phải PII).

[M6]

103 lần dùng "as any" phá type safety

Cần xử lý

AGENTS.md Rule #3 — Strict Database Payload Typing

103 occurrences của as any trên Supabase client trong 16 file. Compiler không kiểm tra sai column, sai type khi insert/update — nguyên nhân gốc của bug "silent attendance insert failure".

const supabase = (await createClient()) as any;  // ← 103 lần

Các file bị ảnh hưởng: lifecycle-actions.ts, session-actions.ts, clearing-actions.ts, franchise-actions.ts, finance-actions.ts và 11 file khác.

Cần refactor riêng trong sprint tới — dùng typed client hoặc generated Database types.
