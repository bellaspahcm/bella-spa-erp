Phần 04

Kiến Trúc Tuần 2 — Chi Tiết Kỹ Thuật

TenantContext v2 — Stale-While-Revalidate Pattern

Vấn đề v1: TenantContext chỉ depend vào auth.status → không reload khi switch tenant. Người dùng thấy loading flash mỗi lần mở app.

❌ v1 — Vấn đề
useEffect([auth.status])
Không reload khi tenant_id đổi → Bug khi switch tenant. Loading flash mỗi lần mở app.
✅ v2 — Giải pháp
useEffect([auth.status, tenantId])
+ AsyncStorage cache 10 phút → tên spa hiện ngay lập tức, background refresh. 
App open → đọc AsyncStorage (fast)
  ↓ render ngay với cache (stale: true)
  ↓ fetch DB background
  ↓ update với data mới (stale: false)
User thấy tên spa NGAY — không có loading flash.

KPI Dashboard — Phân biệt theo Role

Không thể hiển thị cùng 1 bộ KPI cho tất cả — Admin cần biết doanh thu, KTV chỉ cần biết lịch của mình.

KPI Admin / Manager

  • 📅 Lịch hôm nay — tổng số booking
  • 🔄 Đang phục vụ — in_progress sessions
  • 💰 Doanh thu hôm nay — chỉ Admin thấy

KPI KTV / ktv_lead

  • 📋 Buổi hôm nay — được giao
  • ✅ Đã hoàn thành — completed count
  • ⏳ Còn lại — remaining count
💡
Dùng isTechnicianRole(role) từ @bella/shared — không hard-code role === 'ktv'. Khi xuất hiện ktv_lead, senior_ktv → chỉ cần update ROLE_GROUPS một chỗ.

RPC Pattern — rpc_mobile_today_sessions

Thay vì JOIN dài session_logs → bookings → customers → users, tạo Supabase RPC function để mobile gọi 1 lệnh:

// Mobile chỉ gọi:
supabase.rpc('rpc_mobile_today_sessions', {
  p_tenant_id: tenantId,
  p_today: today,
  p_ktv_id: ktvId,   // null → Admin thấy tất cả
})

Fallback Strategy:

Nếu RPC chưa deploy → tự động fallback sang direct join. TODO Tuần 3: xóa fallback sau khi migration apply lên prod.

Debounce Realtime 500ms:

Khi 5 session cập nhật cùng lúc → debounce 500ms → chỉ 1 refetch thay vì 5. TODO Tuần 4–5: thay bằng optimistic update.
