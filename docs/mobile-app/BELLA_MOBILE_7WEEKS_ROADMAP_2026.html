Tuần 6 — Automation Triggers & Reschedule 9.1/10

⚙️ Deliverables

  • ✅ BEFORE trigger (critical path): Trừ kho inventory_items atomic ngay khi session complete
  • ✅ AFTER trigger (deferred): Enqueue accounting_outbox + tạo session_reviews — lỗi không rollback session
  • ✅ rpc_mobile_reschedule_session: dời lịch từ mobile với SELECT FOR UPDATE
  • ✅ RescheduleModal: DateTimePicker với UUID v4 + local timezone

🔧 Critical Fixes (v2)

  • 🔴 Trigger monolith: Tách BEFORE (inventory) + AFTER (accounting+review) → lỗi side-effect không rollback session
  • 🔴 Tenant isolation RPC: v_user_tenant_id ≠ v_session_tenant_id → CROSS_TENANT_VIOLATION
  • 🔴 Race condition: SELECT FOR UPDATE trước khi update
  • 🔴 UUID bug: uuidv4() + react-native-get-random-values
  • 🔴 Timezone bug: formatLocalDate() — không dùng toISOString().split('T')[0]
  • ✅ Audit trail: audit_logs mỗi lần reschedule
Session complete ↓ BEFORE trigger (critical — trong transaction) UPDATE inventory_items SET stock_level = stock_level - qty [atomic] INSERT inventory_logs ↓ AFTER trigger (deferred — sau transaction commit) INSERT accounting_outbox ON CONFLICT DO NOTHING INSERT session_reviews ON CONFLICT DO NOTHING EXCEPTION → RAISE WARNING (không rollback session đã commit)

Phần 05

Kiến Trúc Nổi Bật

RPC-First Mobile API

Mọi thao tác mobile đều thông qua Supabase RPC, không query trực tiếp từ mobile:

  • ✅ rpc_mobile_complete_session — idempotent với client_action_id UUID
  • ✅ rpc_mobile_reschedule_session — tenant isolation + row lock
  • ✅ rpc_mobile_get_my_kpi — commission_earned (hoa hồng thực nhận)
  • ✅ rpc_mobile_get_my_reviews — double tenant + ktv filter
  • ✅ rpc_mobile_get_booking_progress — derived COUNT(*)
  • ✅ rpc_mobile_request_renewal — tạo renewal_request record

Lợi ích: Web và mobile không bao giờ lệch logic — 1 nguồn sự thật duy nhất ở DB layer.

Outbox Pattern — Deferred Side Effects

Tách critical path và deferred side-effects để không để lỗi kế toán rollback session:

BEFORE trigger (session complete)
  → inventory consume [ATOMIC]
  → rollback nếu kho fail ✓

AFTER trigger (deferred)
  → accounting_outbox (enqueue)
  → session_reviews (placeholder)
  → EXCEPTION → RAISE WARNING
  [session đã commit, không rollback]

Kết quả: KTV thấy "Hoàn thành thành công" ngay cả khi accounting worker chưa xử lý.

Derived Source of Truth — Không Dùng Counter

❌ Cách cũ (Dễ drift)

UPDATE bookings
SET completed_sessions =
  LEAST(
    completed_sessions + 1,
    total_sessions
  )

Nếu admin web và KTV mobile cùng complete → counter = 7 dù thực tế chỉ có 6 session

✅ Cách đúng (Derived từ source table)

SELECT COUNT(*)
FROM session_logs
WHERE booking_id = p_booking_id
  AND status = 'completed'
  AND tenant_id = v_tenant_id

Luôn chính xác, không bao giờ drift, idempotent tự nhiên

Idempotency Pattern — Chống Double-tap / Duplicate Action

mobile_processed_actions (UNIQUE constraint trên client_action_id) ↓ RPC nhận p_client_action_id UUID (từ uuidv4() trên mobile) ↓ SELECT EXISTS(...) → v_already_processed = TRUE ↓ IF v_already_processed → RETURN { ok: true, message: 'Đã thực hiện trước đó' } [Không execute lại, không error] ↓ Thực thi logic ↓ INSERT INTO mobile_processed_actions (client_action_id, user_id, action_type)
