## Key Findings & Insights

### Finding 1: Type Definitions ≠ Code Usage

**Phát hiện:**
- Có type definition `re_customers` trong 5 files
- Nhưng KHÔNG có code nào query bảng này
- Type definitions là autogenerated, không chứng minh usage

**Lesson:**
> **"Phải verify cả code ÂN database schema, không chỉ type definitions."**

---

### Finding 2: Planning Assumption vs Runtime Reality

**Assumption ban đầu:**
- Audit nhìn type definitions → giả định `re_customers` được dùng
- Plan migration: `re_customers → Person Center`

**Reality thực tế:**
- Code search: ZERO references
- Real Estate dùng `real_estate_products` thay vì
- `owner_name` là string field, không phải FK

**Lesson:**
> **"Audit code + database + runtime behavior, không chỉ schema."**

---

### Finding 3: Gate 3 Dependency Discovery là Critical Gate

**Giá trị G3:**
- Bắt được assumption sai TRƯỚC KHI code
- Ngăn 40-60 giờ refactor sai target
- Enforce verification, không cho pivot vội

**Nếu skip G3:**
- Day 2: Bắt đầu code migration `re_customers`

## Lessons Learned

### Lesson 1: Gates Are Decision Points, Not Checklists

**OLD thinking:**
- Gate = Checklist items to complete
- Mark items as done, move to next gate
- Focus: Finish checklist

**NEW thinking:**
- Gate = Decision point based on evidence
- Can BLOCK if evidence shows problem
- Focus: Make correct decision

**Day 1 proved:**
- G3 blocked correctly when assumption wrong
- Saved 40-60 hours of wrong work
- Value > finishing all 5 gates blindly

---

### Lesson 2: Verification > Assumption

**OLD approach:**
- Assume `re_customers` used (has type def)
- Plan migration
- Start coding
- Discover wrong later (waste time)

**NEW approach:**
- Assume NOTHING
- Verify: code + database + runtime
- Find evidence
- Then plan migration

**Day 1 result:**
- Verification caught wrong assumption
- Saved team from wasted effort
- Built confidence in process

---

### Lesson 3: Simple Process, Strong Enforcement

**Day 1 applied:**
- Simple: 5 gates, clear checklist
- Strong: CI blocks PRs, can't bypass
- Enforcement: Automatic, not manual review

**Result:**
- G1 active forever (protects all future PRs)
- Team can't accidentally violate
- Low overhead, high protection

---

### Lesson 4: Pause to Verify > Rush to Code

**Decision at G3:**
- Option A: Pause, verify database (chosen)
- Option B: Continue G4/G5, verify later
- Option C: Pivot to `owner_name` immediately

**Why A was correct:**
- Verifying takes 30 min
- Wrong migration costs 40-60 hours
- Pivoting without evidence = new assumption

**Principle:**
> **"Dừng để xác minh > Tiếp tục với uncertainty"**
